# 脚本改造约定

建议每个真实绘图任务保留以下必要内容（并非无条件生成空文件）：

```text
outputs/<task>/
  profile.json             本地画像，注明抽样范围
  selection.md             候选对比、数据契约、决定
  config.json              输入路径、roles、单位、阈值、样式和导出参数
  plot.R 或 plot.Rmd       经审查的可复现改写脚本
  provenance.json          源仓库、commit、path、hash、许可、使用的代码段
  changes.md               主要改动以及统计/数据原因
  environment.txt          R/sessionInfo或Python/依赖版本及执行命令
  figure.pdf/svg/png       仅列实际生成的文件
  validation.md            数值、运行、视觉验证状态及局限
```

## 六个层次

1. 配置：把阈值、颜色和字段集中；参数合法性检查比自动猜测更可靠。
2. 数据读取：列名显式、ID字符化、编码和缺失值显式。报告输入文件哈希，不改原始数据。
3. 转换：函数化ID对齐、长宽转换、排序、过滤、必要归一化；每步检查形状。只有确定输入是未log的数据才log。
4. 统计：若用户提供已计算结果，保留结果，只做显示所需处理；新统计需与研究设计相符。小样本、配对、删失、零膨胀等不能由外观决定方法。
5. 绘图：绑定数据语义而非列位置。对象数量变化时自适应画布、分面、图例和标签；大数据可有透明度、密度/hexbin或分层抽样方案，须记录损失。
6. 导出：固定物理尺寸和字体，使用显式plot对象。ggplot用ggsave；pheatmap/ComplexHeatmap/grid等使用适合的device/draw流程；确保设备关闭。SVG依赖svglite等需检查，不能只改扩展名。

## 常见修复

- `df[, 1:20]`、`[4:24,4:24]`等示例切片改为经检查的名称选择。
- `source("install_dependencies.R")`与`rm(list=ls())`从绘图入口移除；需要的依赖明确列出。
- `setwd("作者电脑路径")`改为命令参数/项目路径；含空格路径正确引用。不要改用户的全局工作环境。
- Rmarkdown顶层代码块中`eval=FALSE`或shell块可能只是说明；提取时不把所有代码文本拼起来运行。
- 热图行标准差为0时Z-score不可用；选择保留常数行并明确色标或有理由地排除，记录数量。
- p=0导致`-log10`无穷，绘图数据可用有记录的下限，统计表保留原值。P值缺失不等于不显著。
- 颜色顺序与factor levels/图例一致，缺失组不能让后面类别错色。
- 重复测量的`group=subject_id`控制连线，连线不会自动修复错误的独立样本检验。
- “样本都是同一个病人”的细胞数据不要给出把细胞当独立样本的生物学P值。
