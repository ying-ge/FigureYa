# 数据语义与设计检查

画像工具是有界的表结构检查，不是统计分析软件。输出默认不含患者ID或具体类别值，不上传任何用户数据。其规则没有能力仅凭数值推断研究设计。

| 输入形态 | 必须确认 | 会改变选型的发现 |
|---|---|---|
| 分组连续测量长表 | 测量单位、组别、subject ID、每对象测量次数 | 配对需连线及配对推断；重复时间点需轨迹/分层模型；仅汇总均值不能画真实小提琴 |
| 数值宽矩阵 | 行/列含义、唯一ID、是否已log/归一化、零/缺失含义 | 样本相似性选相关/降维，基因模式选表达热图；相关矩阵不能再次当表达矩阵计算相关 |
| 原始counts | 非负整数、技术与生物重复、设计矩阵、批次 | 不直接用TPM方法替代counts模型；是否做差异分析由任务决定 |
| 差异结果 | 对比方向、effect类型/底数、raw P或FDR、NA原因、feature ID | log2FC、deltaBeta、PDUI差异不是同一种量；多个contrast不自动合并显著性 |
| 富集结果 | term、方法、方向、显著性、Count/GeneRatio背景 | ORA点图不等同GSEA运行曲线；后者需排名统计量与基因集 |
| 生存记录 | time单位/起点、event=什么、删失、竞争事件、组别 | 生存ROC不同于二分类ROC；非比例风险和竞争风险不能仅改图标题 |
| 效应量表 | estimate、CI/SE、比值或差值、参考组、模型 | 森林图用实际CI，log轴需正值；亚组交互证据与组内显著性不同 |
| 二分类预测 | 真值、阳性类、分数方向、概率/一般分数、验证集 | ROC用排序分数；校准/DCA需有意义概率；生存预测还需要删失处理 |
| 集合 | 成员列表或成员矩阵、重复、集合定义 | 列有ID不是集合定义；集合过多Venn不清晰，确认实际支持的UpSet路径 |
| 边表 | source/target、权重、节点表、有向性、重复边 | Sankey的阶段/流量假设不同于一般网络；避免把关联推成因果流动 |
| 组成表 | count/proportion、分母、闭合总和、零值 | 分母不同不可相加；供体细胞数影响组成估计 |
| 单细胞/空间 | 对象格式/版本、assay/slot/layer、细胞/供体、注释、已有结果 | 细胞不等于独立重复；坐标、邻接、raw与normalized层不能混淆 |
| 基因组信号 | 参考基因组、坐标起点、染色体命名、文件格式 | 大轨道文件不能当普通CSV；跨版本需合法映射 |

## 多文件与规模

以明确的ID做一对一/一对多连接，检查重复、缺失、未匹配和连接前后行数；先确定基因/样本方向再转置。缺失值策略不能只为让绘图函数运行而决定。记录完整流程的过滤数量；画像的重复/分位数仅针对读取的行。

对大表先画像再选择关键列做全量校验。前缀样本可能漏掉尾部错误、罕见组和批次，不能外推总量。不要凭唯一值比例判定ID，也不要从整数值判定测序counts。脚本不自动识别所有日期、编码数值、权重、偏态/多峰或异常测量，应结合元数据和实际分布检查。

支持 `roles.json` 显式覆盖自动候选，例如：

```json
{"id":"受试者编号","group":"处理组","time":"随访月数","event":"终点","score":"模型概率"}
```

这只是列映射，不能代替“终点1代表死亡还是删失”等语义说明。不确定且会改变分析时询问用户；可读文件和其他不受影响的工作继续。
